# Tubekeep testing

Rules and non-obvious mechanics for every test suite in this repo. Violating any of these
produces a failure that points nowhere near its cause, so read the relevant section before
writing the test, not after it goes red.

## Backend suite (`node:test`)

Backend tests are plain `node:test` files colocated with the source (`*.test.js`), run with `cd backend && npm test` (`node --require ./testSetup.js --test`). **`backend/testSetup.js` is load-bearing — don't drop the `--require`.** It repoints `console` at stderr for the run (redirected, not silenced): the runner carries v8-serialized result frames on each child's *stdout*, so an app log line written mid-frame splits it and the run dies with `Unable to deserialize cloned data due to invalid or unsupported version` — surfacing as a whole test *file* failing at its boundary while every test inside passed. Not a flake; don't just re-run.

**A test that needs a *real* server spawns it through `backend/test/helpers/spawnServer.js` — never with a hand-picked port.** Five files (`cors-env`, `api-cache`, `schema-boot`, `rateLimit-proxy`, `ipv6-boot`) run `src/server.js` as a child and drive it over HTTP; `node --test` runs files in parallel, so a shared port means `EADDRINUSE`/`ECONNREFUSED` or — worse — a `/health` poll succeeding against the *other* file's server and asserting against different env (0XC-275). The helper spawns with `PORT=0` and reads the **actually bound** port off the child's `🚀 Server running on http://localhost:<port>` line, so **`src/server.js` must keep logging `server.address().port`** rather than the requested value. It also attaches captured stdout/stderr when the server won't boot. Pass `cwd` for a scratch dir with its own `.env` (`scratchCwd(prefix, contents)` / `removeScratchCwd(dir)`, same module) — `server.js` runs `dotenv.config()` against its cwd and would otherwise read this machine's real `backend/.env` back over any variable the test deleted. In `env` overrides, **a key set to `undefined` deletes** that variable from the child. Three guards in `test/helpers/spawnServer.test.js` fail CI: every `*.test.js` under `backend/` is rejected if it names a `PORT` **or** spawns `src/server.js` itself (a file spawning with no `PORT` silently takes the hardcoded 3001 default), and `src/server.js` is source-checked for the `server.address().port` log. The scans assert their own reach, since a guard that walks nothing passes forever.

### Store contract suites

**`downloadsStore` and `authStore` are each tested as a *contract*, run twice — once per implementation** (`backend/src/services/downloadsStore.contract.js`, 0XC-110; `authStore.contract.js`, 0XC-330). Each ships two impls of one interface and every other test injects the memory one, so the Postgres branch production runs had no execution coverage. The contract registers every case against an injected `freshStore` factory: `<store>.test.js` runs against `createMemoryStore()` (always, no database), `<store>.pg.test.js` runs the *same* cases against `createStore(query)`. **Change one impl and the other's run of the same cases goes red.** Shared and load-bearing:

- **Missing `TEST_DATABASE_URL` skips, never fails**, with a reason naming the variable — a laptop `npm test` stays hermetic and offline. Only an **unset** variable skips; set-but-unusable fails every case. Point it only at a **throwaway** database; the harnesses `TRUNCATE` between cases.
- **Setup goes through the store's own public methods** (`expireForUser`, `markFailed`, `markMoved`), so one set of lines drives both a `Map` and a table.
- **They bypass `db.js` deliberately** — it sets `ssl` unconditionally and would refuse a non-TLS test container. Rather than loosen a production TLS default, each pg harness builds its own `pg.Pool` with `ssl: false` and passes `pool.query.bind(pool)` into the injected-query slot `createStore` already takes, so **no production code changes**; schema comes from `dbInit.js`'s `applySchema` (bringing its column-drift assertion along).
- **A drift guard asserts both impls expose the same method set** (ignoring the memory impl's `_rows`), since the contract can only call methods it knows about. One shared assertion for both stores: `services/storeSurface.js`.

`downloadsStore` specifics — the injected **`backdate`** is the single escape hatch around the interface (`created_at`/`completed_at` are `now()`-stamped and both `interval '1 ms'` clauses need testing); **keep it the only one**, since anything else a harness must reach around the interface for is a gap in the interface. Its pg harness `TRUNCATE`s `downloads` + `users`. **Keep `slowButFresh`** in the grace-window case (old creation, recent completion) — without it, measuring the window from a bare `created_at` instead of `coalesce(completed_at, created_at)` passes.

`authStore` specifics:

- **No `backdate` escape hatch, deliberately** — `login_tokens.expires_at` is a **parameter** of `insertLoginToken`, so expiry is reachable through the interface. Keep it that way; reaching around it here would invent a gap, not cover one.
- **The pg run gets its OWN database** (`<TEST_DATABASE_URL's name>_authstore`, created on demand, truncating `login_tokens` + `users`). Both pg runs need a clearable `users` table and `node --test` parallelizes files, so a shared database makes them delete each other's rows (`downloads_user_id_fkey` failures; 5–6 cases red when the two run alone together). **A third pg contract run must derive its own database too.** The role in `TEST_DATABASE_URL` must therefore be allowed to `CREATE DATABASE`.
- **The pg harness pre-warms `CONCURRENT_CONSUMERS` connections, and that is load-bearing.** `consumeLoginToken`'s single atomic `UPDATE … WHERE used_at IS NULL` is what keeps a magic link single-use, and the memory impl can't fail a test of it. But `pg.Pool` connects **lazily**, so N concurrent queries against a cold pool run *sequentially* and a non-atomic read-then-write `consumeLoginToken` passes. The contract owns the constant and the harness sizes off it.
- **Don't narrow the expiry margin or add a sleep** chasing the surviving `>` → `>=` mutant on `expires_at` — an equivalent mutant; the margin is deliberately a minute because at 1ms clock skew makes the case flaky.

Both suites were verified **by mutation, not inspection** — keep it that way when extending them.

### Frontend a11y suite

**Frontend tests are a Playwright a11y smoke suite** (`frontend/test/a11y/*.spec.js`), run with `cd frontend && npm test` (`npm run test:ui` for the UI; `npm run test:install` fetches the browser on a fresh clone). Deliberately a handful of high-value assertions — **not** component unit testing, not a full WCAG audit: it renders real routes in a real browser to catch the one defect class every other gate is blind to (the invisible focus ring, 0XC-111, shipped with lint, build and the backend suite green).

- **`focus-ring.spec.js`** — walks the real tab order on `/login` asserting `outline-style: solid`, width ≥ 2px, offset 2px and a **non-transparent** `outline-color` on every focusable control; the colour check catches this bug class, since the forms plugin's reset leaves the geometry healthy and only zeroes the colour. Also: a mouse click draws no ring (`:focus-visible` must not fire on pointer input — asserted on a *button*, since per the CSS UI spec `:focus-visible` always matches a text field whatever the modality), and `--focus-ring` resolves in both themes with the ring compared against the token, not a hard-coded value. Its last test is a **regression guard**: it strips the `:root` prefix off the app's rule in the live page and asserts the ring goes invisible.
- **`aria-disabled.spec.js`** — covers the aria-disabled convention (see *Styling system*) at all three call sites (`UrlInput`, `FormatSelector`, `MoveToCloud`) through their real routes with the API stubbed. Each asserts all three halves together — marked `aria-disabled`, still keyboard-focusable, `aria-describedby` resolving to non-empty text — because a dangling describedby id is the silent failure. It reads the native `disabled` **IDL property**, not Playwright's `toBeEnabled()`, which follows the *accessibility* notion of disabled and would pass for exactly the markup the convention forbids; for the same reason, clicking an aria-disabled control to exercise its click guard needs `{ force: true }`.

**The suite is hermetic and enforces it** (`test/a11y/support/hermetic.js`): every request is intercepted, localhost passes, anything else is aborted and recorded. `support/fixtures.js` extends Playwright's `test` with an auto-used `hermetic` fixture whose teardown fails any test that leaked (naming the URL) and fails a test that never called `hermetic.prepare()`, so the assertion can't go vacuous. No backend, database or `yt-dlp` needed; the API is stubbed per test via `hermetic.prepare({ theme, api })`. The wrinkle: `index.html` loads Tailwind (and its **forms plugin**) from `cdn.tailwindcss.com` at runtime, and that plugin's `:focus` reset is precisely the adversary the focus ring must out-rank — block it and the assertions go quietly vacuous. So the CDN request is fulfilled from `frontend/test/stubs/tailwind-cdn-stub.js`, reproducing that rule at the specificity the CDN ships it (`[type="url"]:focus` etc., `(0,2,0)`) and stubbing the `tailwind` global. **If the app stops loading Tailwind from the CDN, or the CDN's forms build changes shape, refresh that fixture** — a stale adversary weakens the suite without turning it red. `@playwright/test` is pinned to an exact version because it determines the browser build.

### CI

**`.github/workflows/ci.yml`** gates every PR with four parallel jobs: `lint` (root `npm run lint`), `test` (`cd backend && npm test`), `build` (`cd frontend && npm run build`), `frontend-a11y` (`cd frontend && npm test`). It needs no `yt-dlp`, `ffmpeg`, network, or external service (`backend/test/ytdlp.test.js` fakes the binary; the a11y suite aborts non-localhost requests). The one database is a **`postgres:16` service container** on the `test` job — deliberately a container, not a Neon branch (free, no secret, nothing to clean up, no Neon-specific SQL) — whose `TEST_DATABASE_URL` un-skips the two pg contract runs. The service is **additive**: unset the variable and those files skip while everything else runs identically. `frontend-a11y` is the only job that downloads a browser; it caches `~/.cache/ms-playwright` keyed on `frontend/package-lock.json` and still runs `playwright install --with-deps` on a cache hit (OS libraries aren't cached). `deploy.yml` runs the same four checks (its `lint`/`test`/`build-frontend`/`frontend-a11y` jobs — not its separate `build` job that builds the image) before the image build, since it also fires on the daily scheduled rebuild and manual `workflow_dispatch`.
